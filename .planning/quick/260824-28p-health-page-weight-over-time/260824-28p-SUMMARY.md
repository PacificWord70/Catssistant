## The thing that had to be solved first

`Cat.weight` is a **single scalar**. A time series needs many dated readings, so
there was nothing to plot. `types/healthRecord.ts` already modelled exactly the
missing piece and was **completely unused** — no storage, no slice, no
references — with a doc comment that anticipates this chart. The work was to
make that type real, not to design something new.

## Decisions

1. **`Cat.weight` stays the profile's current weight; HealthRecord is the
   history.** Nothing existing breaks. Reversible later into a derived read.
2. **The existing profile weight is not back-filled as a chart point.** We know
   the number, not the date it was taken. Putting it on a timeline would invent
   a measurement date. The empty state explains this rather than hiding it.
3. **No charting dependency** — hand-drawn SVG. Deps need team discussion.
4. **X is proportional to elapsed time, not index.** Even spacing would imply a
   weighing cadence the owner never kept.
5. **Trend is first-to-last, not a fitted slope** — a regression over five
   readings implies precision the data does not have. "Steady" is a 0.1lb band
   because scales disagree with themselves by ounces.
6. **No breed-typical weight baseline.** `lib/breeds.ts` has energy,
   friendliness, grooming, vocality — no weight. A healthy-range band would mean
   inventing veterinary data.

## Verification

Typecheck clean, lint 0 errors, **143 tests passing** (128 existing + 15 new).
Exercised in the browser against seeded data, then the seed was removed:

- 5 readings — time-proportional spacing confirmed (a 14-day gap renders visibly
  narrower than a 79-day one), Y inverted correctly, ticks padded past the data
- 1 reading — dot centred, synthetic tick band, no collapse
- 0 readings — empty state
- Trend `+1.4 lbs / +15.2% over 191 days` verified against the input by hand
- Last vet visit correctly picked the later of two events; active medications
  correctly counted 2 started − 1 stopped = 1
- Log form: rejects an empty weight, saves with a real UUID, closes, persists

Two bugs found and fixed by looking: `set-state-in-effect` on the cat selection
(replaced with derivation at read time), and "1 readings"/"1 active medications"
pluralisation.

One gap found by looking: the `Withvet` fixture showed "no vet visit" while
having a vet practice on its profile. Not a bug — but the page was ignoring
recorded data, so the card now falls back to the practice name.
