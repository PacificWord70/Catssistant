# Quick Task: Colored cat tree artwork + fluid site width

Two unrelated changes requested in one session. **Two atomic commits**, per the
one-logical-change-per-commit rule.

## Task 1 — Replace the home page cat tree with colored, code-drawn artwork

Heidi supplied a new hand-drawn cat tree (line art, no colour). It replaces the
current `/images/cat-tree.png` on the home page and should be committed to the
repo in colour.

**Format decision: inline SVG in a React component, not a raster.**

`.gitignore` blocks `*.png/jpg/jpeg/gif/webp`, and CLAUDE.md says artwork must be
drawn in code so real hand-drawn work can drop in later. SVG is neither ignored
nor raster, and a component lets the artwork and the nav overlay share one
coordinate system. A committed `.tsx` full of vector paths satisfies "commit the
image" without fighting the ignore rules or adding a negation entry.

**Palette** (existing brand tokens only — no new colours invented):

| Element | Colour | Token |
|---|---|---|
| Ink / outline | `#6B4A34` | `brand-brown` |
| Posts (sisal) | `#E7C9A9` | `brand-tan` |
| Perch planks, sling, one pom | `#F26A1B` | `brand-orange` |
| Box, one pom | `#5F8AA8` | `brand-slate` |
| Body panel | tint between `brand-cream` and `brand-tan` | derived |
| Base | `#6B4A34` | `brand-brown` |

Orange carries the accents, slate is the secondary, tan/cream is the structure.

**Nav anchoring.** The six links are currently absolutely positioned at
percentages tuned to the *old* PNG, so they all have to move. Heidi has said the
new tree's buttons will differ and she will assign them once she sees it on
screen. So the component separates two things:

- `ANCHORS` — named spots on the drawing (`topPerch`, `leftPerch`, `boxDoor`,
  `crescent`, `hammock`, `lowShelf`) in SVG viewBox coordinates
- `PERCHES` — nav item → anchor name

Re-assigning a button becomes a one-word edit, and nudging a spot touches one
coordinate pair. Initial assignment is provisional and expected to change.

**Files:** new `components/CatTreeArt.tsx`; edit `components/CatTree.tsx`.
The old `public/images/cat-tree.png` is left on disk (tracked from before the
no-images rule) but is no longer referenced — flag to Heidi, do not delete
unasked.

**Commit:** `feat(home): draw the cat tree in colour`

## Task 2 — Make the site width follow the screen

Current shell is capped at `max-w-5xl` (1024px) in two places, so a desktop
monitor shows wide empty apricot margins:

- `app/layout.tsx:31` — `<main className="max-w-5xl mx-auto px-4 py-8">`
- `components/NavBar.tsx:60` — same cap on the nav's inner container

Widen both to a fluid container that fills most of a large monitor and steps its
gutters down on small screens.

**Out of scope, deliberately:** the `max-w-2xl` / `max-w-3xl` caps on forms and
reading pages (`about`, `breeds`, `guides`, `cats/new`, `cats/[id]`). Those are
line-length caps, not layout accidents — a form stretched across 1600px is worse,
not better. Only the shell changes.

**Commit:** `style(layout): let the page width follow the screen`
