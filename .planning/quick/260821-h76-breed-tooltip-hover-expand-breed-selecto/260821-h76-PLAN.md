# Quick Task 260821-h76

Breed tooltip hover-expand, breed selector reopen fix, bigger schedule emojis.

Three small UI changes requested together, plus two malformed Tailwind classes
found in the same lines while investigating. Four logical changes, four commits.

## Task 1 — Expand the breed tooltip after five seconds

**Files:** `components/BreedTag.tsx`

**Action:** The tooltip shows `breed.description` under `line-clamp-4`, so long
breed paragraphs are cut off with no way to read the rest. Add a timer started on
mouse enter that, after 5s of continuous hover, drops the clamp and shows the
full paragraph. The timer must be cleared on mouse leave and on unmount, or a
pending callback fires against an unmounted component.

The tooltip is `pointer-events-none`, so the mouse never enters the tooltip
itself — the hover being timed is on the trigger, which stays true while the
expanded tooltip is open.

**Verify:** Hover a breed pill on `/cats`, wait 5s, the full description appears.
Leave before 5s and it never expands.

**Done:** Tooltip expands only after 5s of unbroken hover; no timer leaks.

## Task 2 — Keep the breed list open after picking a breed

**Files:** `components/CatForm.tsx`

**Action:** Selecting an option runs `setBreedOpen(false)`, but the same handler
calls `e.preventDefault()` on mousedown, which keeps focus in the input. Because
`onFocus` only fires when focus is *gained* and the input never lost it, the list
cannot reopen — the user has to click out and back in before adding a second
breed.

Stop closing the list on selection. The breed picker is multi-select and the list
already filters out anything already chosen, so staying open is both the fix and
the better behaviour. Also add an `onClick` handler that reopens the list, so a
click on an already-focused input still works.

**Verify:** On `/cats/new`, add two breeds in a row without clicking away.

**Done:** Consecutive breeds selectable with no intervening click-out.

## Task 3 — Enlarge the schedule category emojis

**Files:** `components/ScheduleCalendar.tsx`, `app/schedule/page.tsx`

**Action:** Calendar day cells render the category emojis at `text-[10px]`, small
enough to be unreadable at a glance; the per-day event list uses `text-xl`. Raise
both. The calendar cells are `aspect-square` in a 7-column grid, so the emoji row
has to stay small enough not to push the day number or overflow the cell.

**Verify:** `/schedule` — emojis legible in day cells and list, no cell overflow.

**Done:** Both sizes raised, calendar grid layout unchanged.
